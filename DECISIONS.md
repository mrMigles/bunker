# Архитектурные и дизайнерские решения

Документ фиксирует решения, принятые там, где ТЗ допускает разные трактовки или где пришлось отступить от него.

## Стек и сборка

| Решение | Почему |
|---|---|
| **TypeScript 6.0** (не 7.x) | typescript-eslint пока поддерживает только `<6.1`. Рантайм не страдает: Vite/tsx транспилируют сами. |
| **Colyseus 0.18** (`@colyseus/core` + `@colyseus/ws-transport`), клиент `@colyseus/sdk` | Последние стабильные версии на момент разработки. Мета-пакет `colyseus` не нужен. |
| **Express** внутри Colyseus (`express:` хук `defineServer`) | Один Node-процесс раздаёт статику клиента, HTTP API (`/api/room/:code`, `/api/rooms`, `/api/saves`) и WebSocket. |
| `packages/shared` потребляется **как исходники** (без сборки) | tsx на сервере и Vite на клиенте понимают TS напрямую; нет шага `build` для shared. |
| UI — **ванильный TS** + крошечный хелпер `h()` (`client/src/ui/dom.ts`) | Никаких фреймворков в бандле; UI-оверлей простой. |
| Порт сервера: `SERVER_PORT` (dev) / `PORT` (только production) | Dev-инструменты (превью, Vite) часто выставляют `PORT` под клиента. |

## Синхронизация состояния (отступление от «всё через Schema»)

Мир — **обычный JSON-объект** (`World` в `shared/src/types.ts`), его симулирует общий код из `shared`. Клиентам уходит **структурный дельта-патч** (`shared/src/net/diff.ts`) раз в тик (20 Гц):

- публичный вид (`publicView`) считается один раз и диффается против последнего отправленного снимка;
- приватный вид (`privateView`: скрытая цель, личный тайник, карты в руке, галлюцинации) — отдельно для каждого клиента;
- массивы примитивов (сетка породы 48×32) отправляются **дельтами по индексам** (`{"~a": [[i, v], …]}`).

Почему не Colyseus Schema для мира:
1. симуляция и тесты работают на чистых объектах без зависимостей от Colyseus;
2. сохранение в SQLite = `JSON.stringify(world)`, восстановление без маппинга;
3. фильтрация приватного состояния — одна функция `privateView` вместо разметки StateView по всему дереву;
4. нет двойной модели (Schema ↔ логика).

Colyseus используется для комнат, матчмейкинга, транспорта, реконнекта и лимитов. Сообщения: `i` (ввод), `a` (команды), `chat`; сервер шлёт `s` (снимок), `p` (патч), `fx` (эффекты).

## Комнаты и коды

- `LobbyRoom` из ТЗ объединён с `GameRoom`: у комнаты фаза `lobby`. `roomId` = 5-символьный код (без O/0/I/1).
- Вход по коду: `GET /api/room/:code` поднимает комнату из SQLite, если её нет в памяти, затем `joinById`.
- Игрок идентифицируется постоянным `pid` из localStorage → перезагрузка вкладки возвращает его в своего персонажа.
- Хост — первый вошедший; при выходе передаётся следующему онлайн-игроку.

## Мир и движение

- Сетка 48×32 клетки, **уровень = 2 ряда**. Копание идёт **слотами** (колонка × уровень = 2 клетки) — так проходимость всегда однозначна; время копания = сумма по обеим клеткам по таблице скоростей из §14.
- Вертикаль — только по лестницам (объект `ladder` в шахте). Люк наверх закрыт в обычные дни (выход — через терминал вылазки).
- Движение игрока: клиентское предсказание + реконсиляция по `seq` (сервер применяет каждый ввод сразу, с бюджетом `dt` против спидхака).
- Ввод отправляется из `setInterval` 20 Гц, не из `requestAnimationFrame` — чтобы работать и в фоновых вкладках.
- Стартовый бункер: 6 комнат (ТЗ перечисляет 5, но радио, Доска дел и Игровой стол «в Столовой с самого начала» — поэтому Столовая добавлена). Стартовые комнаты «довоенный бетон» (`sturdy`): не обваливаются.

## Время

- День = `dayLength` реальных секунд (по умолчанию 360) на 06:00→22:00 игрового времени. Нужды заданы «в сутки» и пересчитываются через игровые часы.
- Ночь (22:00→06:00) — это Совет (≤ 2 мин, ускоряется «Готов»). Восемь часов сна симулируются пакетно в конце Совета: питание/вода из пайков, сон (койка 80 / пол 40 бодрости, храп), энергосеть, фильтр воздуха, рост растений в темноте.
- «Скоротать время»: если все живые игроки отдыхают (или в «Аквариуме») — ×3.

## Баланс (отступления от стартовых чисел §14)

- **Потребление энергии уменьшено вдвое** (свет 0.05, фильтр воздуха 0.15, водоочистка 0.2, гидропоника 0.15 кВт на комнату), **велосипед 0.8 кВт** вместо 0.5, аккумулятор 6 кВт·ч. С числами §14 стартовый бункер требовал ~4 человек, непрерывно крутящих педали. Сейчас один «велосипедист» держит базу, а дизель/термо/солнце реально освобождают руки.
- Урожайность подобрана так, чтобы 3 лотка давали ≈ 3 пайка в сутки (как в §14).
- Свет в комнатах горит, только когда в них кто-то есть (гидропоника — всегда днём).
- Пайки на Совете — основной приём пищи; днём боты перекусывают, только если голодны.

## Действия

- Удержание E: действия с флагом `hold` (спасение, тушение) отменяются при отпускании; длительные (педали, сон, отдых) — переключаются по E и отменяются шагом.
- Клавиши 1–7 выбирают вариант в подсказке действий (в ТЗ «быстрые слоты»: у нас нет рюкзака внутри бункера — только руки, поэтому цифры отданы под варианты действий). Z/X — листать варианты.
- Несколько персонажей на одном объекте ускоряют работу (+60% за каждого).

## Боты

- Utility AI + расписание (подъём, работа, обед, досуг, сон), дела с Доски дел с резервированием, досуг по вкусам профессии, разговоры парами, отношения.
- «Аквариум» (H) и отключение игрока — одна и та же реализация: персонаж игрока ведёт бот-мозг (`isBotDriven`).

## Играбельность: проход геймдизайнера (день 23.09)

Метод: играл за новичка в браузере, затем закрепил сценарий в e2e (`node scripts/e2e/newcomer.mjs` при запущенном `pnpm dev`) и померил цифрами: `scripts/balance/combat-probe.ts` (исходы стычек по размеру отряда), `scripts/balance/prologue-probe.ts` (что приносят в прологе одни боты), `pnpm sim` (10 дней на ботах).

### Вылазки: «сразу убивают»

Что было: отряд собрать из жильцов было нельзя — только «Присоединиться» себе, то есть одиночка шёл с ножом. Растяжка давала +45 шума и будила всё здание, враги замечали за ~1 с, `siteFight` втягивал в бой всех не спящих врагов здания, а поражение убивало каждого с шансом 40%. Замер: одиночка погибал в 25–35% стычек даже с двумя собаками и в 5% случаев переживал группу из трёх; отряд из двух выигрывал почти всё.

Решения:
- **Отряд по умолчанию.** Тот, кто открыл терминал, сразу ведёт отряд, к нему добавляются двое самых подходящих жильцов (военный/врач/шахтёр/инженер, здоровье, сила, ловкость), и набирается базовый набор. В сборах можно убрать любого бота «×», взять другого («+ Имя (профессия)») или нажать «Автоподбор». Дома всегда остаются минимум двое. Одиночный выход разрешён, но с явным предупреждением.
- **Набор считает сервер** (`expKit`), а не клиент: прежняя кнопка слала набор раньше, чем сервер добавлял игрока в отряд, и набор оставался пустым.
- **В бой втягиваются только те, кто рядом**: в тревоге — до 9 клеток на том же этаже, бодрствующие — до 6, спящие — до 3.
- **Замечают медленнее** (55 вместо 95 в секунду, при скрытности 25 вместо 45): у игрока есть несколько секунд, чтобы увидеть «!» и уйти или спрятаться.
- **Растяжки видны заранее**: за 2–3 клетки по ходу движения со светом их замечают почти всегда, в темноте — реже. Замеченную растяжку перешагивают. Незамеченная: −14 здоровья и +30 шума вместо −18 и +45.
- **Поражение — это раны, а не смерть**: гибель только с шансом 5% × опасность места, остальные возвращаются с 12–30 здоровья, возможно с кровотечением, без добычи и с половиной припасов. Замер после правок: отряд из 2–3 человек выигрывает 90–100% типичных стычек, смертей 0.
- **Дорога вдвое быстрее** в реальном времени (путь — переход, а не геймплей), засад в первые три дня вдвое меньше.
- **Карта**: в начале известны соседи бункера, их соседи и всё в радиусе короткого перехода — 7–13 мест вместо 4. В карточке места показаны «Возможная добыча», «Риски», время в пути и обысканность.
- Боевой отряд, в котором нет живых игроков (автовылазки бригадира), решает дорожные стычки абстрактно: раны и потеря части добычи.

### Пролог: «много времени и мало локаций»

Что было: 90 секунд, 4 дома, а боты за первые 20 секунд уносили 35 из 44 предметов — игроку оставались пустые дома и минута ожидания.

Решения:
- **60 секунд, 6 домов** (улица 58 клеток), люк посередине. Добычи больше (~52 предмета).
- **Риск в обмен на награду**: важные вещи (коробки еды, бутыли воды, аптечки, инструменты, кирка, семена) лежат чаще в дальних домах и на верхних этажах, мелочь валяется на улице.
- **Боты собирают только первые этажи в 13 клетках от люка**, носят по 2 вещи и тратят ~1.4 с на обыск — хорошее достаётся игрокам.
- Предупреждения «15 секунд — к люку!» и «5 секунд!»: тосты и строки в журнале, объясняющие наказание (ожоги и радиация).
- **Стартовый запас бункера поднят** (8 консервов, 14 воды, 1 медикамент, 2 трубы): одни боты дают ~2 дня еды, игрок добавляет сверху. Новичок не начинает в кризисе.
- Рендер улицы больше не завязан на ширину 40 клеток: люк, вывески домов и машины берутся из данных пролога.

### Бункер: «всё слишком сумбурно»

- **Панель «Задачи»** (слева сверху, как на макетах) — один источник ответа на вопрос «что делать».
  - Срочное: без сознания, пожар, налёт, еда и вода меньше чем на день.
  - Потребности: еды на N дней, вода, садится аккумулятор, душно, сломанное оборудование, не хватает коек.
  - Обучение первых трёх дней: покрутить генератор → разметить комнату → собрать вылазку → пережить первую ночь; каждый шаг засчитывается делом.
  - Клик по задаче ведёт персонажа к объекту и открывает его действия. Панель сворачивается, состояние запоминается.
  - Список общий для всех игроков (`w.mods.objectives`, `sim/objectives.ts`).
- **Бригадир не действует за спиной живого игрока**: при активных игроках он не уводит людей на вылазки, а комнаты размечает не раньше 3-го дня и только если двое суток никто ничего не размечал. Нехватки показываются в «Задачах», решают игроки. В партиях из одних ботов и в «аквариуме» бригадир работает как прежде.
- **Памятные вещи из пролога сами расставляются** как декор в жилом отсеке, столовой и на складе (+уют) и не валяются у шлюза, забивая список «Рядом с вами».
- **Действия обороны** («Заложить дверь», «Растяжка у входа») появляются, только когда налёт реален: заметность ≥ 30, тревога или 4-й день.
- **Одинаковые действия** от соседних объектов показываются один раз.
- **Стартовый жилой отсек** — 8 клеток (4 койки вместо 2).

### Интерфейс

- Карточки персонажей в лобби были нечитаемы (тёмный текст на тёмной карточке после перехода на тёмную тему) — светлый текст, выделенные характеристики и цель.
- На `body` висит класс режима (`mode-bunker|combat|site|map|table|prologue`); панели бункера (журнал, карточка персонажа, действия) прячутся в режимах, где они наезжали на интерфейс боя, вылазки и стола.

### Второй проход: здание, стройка, ввод

- **Незапертые двери открываются, когда в них входишь** (+4 шума, при скрытности +1). Раньше персонаж упирался в закрытую дверь у входа, и новичок не понимал, почему нельзя пройти. Запертая дверь останавливает, один раз показывает тост и пишет в журнал, чем её вскрыть. Навигация мышью прокладывает маршрут сквозь незапертые двери.
- **Подсказка «что сейчас делать» внутри здания** зависит от ситуации: «вас ищут», «темно — фонарик (L)», «щёлкните ◇ (N)», «идите дальше: A/D, W/S», «здание обыскано — к выходу». Журнал вылазки раскрыт по умолчанию, показывает 4 последние строки.
- **Стройка**: в начале палитры — «★ Сейчас нужно: …» с причиной (та же логика `neededRoom`, что у бригадира). В режиме стройки прячутся «Задачи», журнал, карточка персонажа и панель действий: раньше палитра наезжала на них.
- **«Задачи» только днём**: ночью совет сам ведёт по шагам.
- **Короткое нажатие клавиши движения больше не теряется**: ввод опрашивается 20 раз в секунду, и нажатие, отпущенное между опросами, пропадало. Теперь оно засчитывается на один опрос.
- **Портрет учитывает пол персонажа** (в атласе 2 мужских и 2 женских портрета): раньше всем профессиям вне списка доставалась девушка-разведчица.
- В e2e новичка добавлен обыск: отряд проходит здание, обыскивает видимые ящики и приносит добычу.

### Третий проход: опасные вылазки в живом клиенте

- `node scripts/e2e/dangerous-sortie.mjs [N] [тип]` — отряд по умолчанию идёт в самое опасное из известных мест, обходит все комнаты, обыскивает всё, дерётся со всеми встречными (за бездействующего игрока в бою планирует бот). Результат: 0 смертей в 7 завершённых вылазках на фермы, заправки, метро и воронки (опасность 1–3; ещё 2 сессии оборвались из-за падения headless-браузера). Ранения бывают — отряд приходит с 31–100 здоровья, иногда с травмой ноги. Так и задумано.
- **Замеченный гнилой пол проходят осторожно** (+8 к броску): раньше «Стой! Впереди гнилой пол» ничего не давало, и боец всё равно проваливался.
- **Освобождение GPU-ресурсов при перестройке здания** (геометрии, материалы, текстуры). Перестройки стали частыми, потому что двери открываются на ходу. Замер `scripts/e2e/leak-probe.mjs`: число геометрий, текстур и шейдеров и JS-куча стабильны в бункере, на карте и в здании. Редкие «Target crashed» в headless-Chromium после 5–10 минут связаны с программным WebGL (SwiftShader), рост памяти игры не подтверждается.

## Итерация 2: стройка, движение, бой в духе XCOM, экономика, прокачка

### Стройка «не работает»
- **Причина 1**: вложенный слой HUD (`.layer` с подписями внутри `.layer`) из-за правила `.layer > * { pointer-events: auto }` превращался в невидимую стену поверх канваса и **съедал все клики по миру**: разметку стройки и ходьбу по клику. Правило `.layer > .layer { pointer-events: none }`.
- **Причина 2**: все допустимые места были за краем кадра. В режиме стройки камера теперь отъезжает на весь бункер, а подходящие места для выбранной комнаты подсвечены зелёным.
- **Комнаты друг над другом**: теперь можно ставить прямо под или над выкопанной комнатой, лестница появляется сама, как только выкопаны обе клетки (`RoomInst.stair`). Раньше вниз можно было только через отдельную шахту, и об этом никто не знал.
- Копка на новом уровне застревала: соседняя клетка, выкопанная сверху, становилась недостижимой ямой, а доступ выбирался сбоку, из ямы. Бот теперь перебирает все стороны подхода (`slotAccesses`).
- Копка вдвое быстрее и идёт по игровому времени (`timeMult`), каркас тоже.
- Боты в рабочие часы (8–12, 13–18) не садятся за настолки и бросают досуг, если ждёт дело срочностью от 0,4.
- e2e: `scripts/e2e/build.mjs` — B → палитра → подсвеченное место → клик → комната готова.

### Движение «лагает и слишком быстрое»
- Скорость: ходьба 3,2 → 2,2 кл/с, бег 5,2 → 3,6, лестница 2,6 → 2,0.
- Чужие персонажи ведутся с постоянной скоростью между пакетами сервера (`CharView.glide`), а не экспоненциально: раньше был ход «рывок — торможение» 20 раз в секунду. Так же в здании и прологе.
- Шаг ног привязан к фактической скорости, ноги не скользят.

### Бой «странный, сразу убивают» → как в XCOM
- Вместо одновременного планирования — **фазы**: каждое действие бойца выполняется сразу (`actNow`, команда `cact`). После «Конец хода» (или по таймеру) боты-союзники доигрывают, затем враги перепланируют по текущей обстановке и ходят по очереди (`enemyPhase`). Бездействовавший игрок к таймеру получает ход бота.
- Экономика ОД: переход до 4 клеток — 1 ОД, до 8 — 2 ОД (было: 1 клетка = 1 ОД, 3 клетки = 2 ОД). «Шаг и выстрел из винтовки» укладывается в ход.
- Зоны движения: синие — после перехода ещё можно стрелять, жёлтые — рывок. Занятые клетки не подсвечиваются.
- Бойцы крепче: 20 + 4 × ВЫН здоровья (было 12 + 4 × ВЫН) и в бой минимум с 60% (раньше раненый входил с 15%). Время хода 45 с.
- Замер (`scripts/balance/combat-probe.ts`): 0 смертей в 300 стычках; одиночка против троих заканчивает бой с 12–24 здоровья, отряд из 2–3 — с запасом. e2e `scripts/e2e/combat.mjs`.

### Провизия и вылазки ботов
- Проверено симулятором: без вылазок еда кончается к 4–5-му дню, к 11–12-му гибнут все, даже если бригадир строит грядки (`pnpm sim --initiative 0`, `--human 1`).
- **«Отправить без меня»**: жильцы идут в выбранное место сами. Исход определяет сила отряда против опасности места: чисто / тяжело / провал. Сила — характеристики, оружие, здоровье, уровень; угроза — 4,5 × опасность + разброс 7. Шансы показаны в сборах до отправки (`sortieOdds`). Замер (`scripts/balance/bot-sortie-probe.ts`): двое в месте опасности 1 — 70% чисто, 30% тяжело; в месте опасности 2 — 40% провалов; в месте опасности 3 — провал всегда. Трое в месте опасности 2 — 40% чисто, 60% тяжело. С игроком отряд сам выбирает бои и что обыскивать, поэтому опасные места — для живых игроков.

### Прокачка
- Опыт: половина опыта навыков, +2 за каждую завершённую работу, +3 за обысканный ящик, +25 за возвращение с вылазки, +15 за выигранный бой (+6 за проигранный) и +4 за каждого поверженного врага.
- Уровни: 60, 180, 360, 600… (`30·(n−1)·n`), до 10. Уровень даёт +1 здоровья в бою и силу в автовылазках.
- На каждом уровне — выбор одного из трёх умений, одно из которых подходит профессии; боты выбирают его сами. Умения делят пространство имён с чертами карточки (`hasTrait`), так что «Выносливый», «Золотые руки», «Крепкая спина» и другие работают как одноимённые черты. Новые умения: «Меткий» (+10 к попаданию), «Проворный» (+1 ОД), «Живучий» (+8 здоровья), «Санитар» (лечение ×1,5), «Тень» (замечают на треть медленнее), «Мародёр» (+1 находка из ящика).
- UI: уровень и полоска опыта в HUD, окно выбора из трёх карточек (открывается само, когда на экране ничего нет), умения в карточке персонажа.

## Итерация 3: анимации, обыск, напарники, интерком, разговоры, мини-игры, карта, живой мир

### Анимации (ноги, атаки, «дрыгание» сидя и стоя)
- **Ноги.** Фаза шага теперь накапливается (`phase += dt · 2π · скорость / длина шага`), а не вычисляется как `sin(t · f)` с растущим `t`. Раньше любое изменение скорости (разгон, пакет с сервера) скачком сдвигало фазу, и ноги дёргались. Полный цикл шага — 1,5 клетки при ходьбе и 2 при беге: ≈1,4 шага в секунду вместо ≈4.
- **Ходьба или стойка** определяется по сглаженной скорости с гистерезисом: пойти — выше 0,45 кл/с, встать — ниже 0,18. Сетевые микросдвиги и подсадка на стул больше не переключают позу туда-сюда.
- **Плавные позы.** Каждый кадр целевая поза смешивается с предыдущей (скорость зависит от вида позы). «Сел ↔ встал», «лёг ↔ встал», «работаю ↔ стою» перетекают, а не щёлкают.
- **Атаки.** `CharView.act()` — одноразовые жесты поверх базовой позы: замах и удар с шагом вперёд (труба, лом, бита), выпад (нож, кулаки), выстрел с отдачей, бросок, отшатывание при попадании, перевязка. Оружие видно в руке (`setWeapon`): и в бою, и на вылазке по снаряжению отряда. Со стрелковым оружием боец в бою держит стойку «на прицеле». Враги (не-гуманоиды) при попадании отшатываются.

### Контекстное меню «не всегда понятно, когда появляется»
- **На вылазке меню «Рядом с вами» теперь видно всегда, когда рядом есть что делать.** Раньше оно открывалось только после клика по объекту. Первое действие подсвечено, и E выполняет его. ↑/↓ листают (в это время они не двигают персонажа, лестницы — на W/S). Цифры и клик мышью работают по-прежнему.
- Так же в бункере: E — выделенное действие, ↑/↓ — выбор, подсказка «↑↓ выбор · E действие» в заголовке. Если рядом новый набор действий, выбор сбрасывается на первое, самое важное.

### Обыск как в State of Decay 2
- **Нажать E** — тихий обыск в обычном темпе.
- **Держать E** (или кнопку мышью) — «быстрый обыск»: в 2,5 раза быстрее, +4,5 шума в секунду и шанс уронить что-то с грохотом (+12 шума). Отпустили — снова тихо. Прерванный обыск продолжается с того же процента.
- **«Детальный осмотр» убран**, как вы и просили. Записки, тайники и шатающаяся ступенька теперь замечаются сами, если стоять рядом. Со светом и «Орлиным глазом» быстрее; то, что открывает прочитанная подсказка, находится сразу.
- **«Обыскать комнату всем отрядом»**: каждый напарник идёт к своему ящику, закончив — берёт следующий. Выходит быстро, но шумно (+6 на старте, шум растёт, пока ищут вдвоём и больше).
- **Обычный обыск напарники не делят**, они стоят на стрёме. Пока вы ищете, вас замечают на 25% медленнее, а напарник первым видит угрозу и говорит об этом вслух. Так у ботов есть работа при обычном поиске, а для скорости есть обыск комнаты.

### Напарники
- **Каждый держит своё место**: сзади, впереди, дальше сзади… относительно направления лидера. Скорость у всех немного разная, поэтому они не ходят строем и не сливаются в одну фигуру. Пока лидер работает, напарник смотрит в другую сторону.
- **Реплики**: раз в 16–30 секунд — по ситуации: на стрёме, «тише, грохочешь!», «темно», «рюкзак трещит», находка или пустой ящик, «Стой! Впереди кто-то есть». Над головой появляется облачко.

### Побеждённых можно обыскать
- **В здании** каждый поверженный враг оставляет «Тело», «Тушу» (звери) или «Обломки» (дрон) ровно с тем, что у него было. Обыск тела — 2,5 секунды. Раньше добыча с боя падала в рюкзак сама и незаметно.
- **На дороге** после боя на карте появляется блок «💀 Тела после боя» со списком и кнопкой «Обыскать тела». Если уйти дальше, тела остаются у дороги.

### Оружие и настольные игры «не встречаются»
- Проверил: оружие лежало почти только в армейских ящиках дальних локаций, а настолки выпадали в 5–10% из редких контейнеров. Главное — **«Инвентарь» открывал доску дел**, склада не было вовсе, поэтому стартовые трубы было не увидеть.
- Теперь **«Инвентарь» открывает вкладку «Склад»**. На ней всё по разделам: еда и вода, **оружие и защита**, медицина, инструменты, материалы, семена, досуг, **настольные игры**.
- **Добыча**: трубы и ножи попадаются в обычных стеллажах и ящиках с инструментами. У тел — нож, труба, иногда пистолет и «коктейль». В шкафчиках — ножи и обрез. Новый контейнер **«Полка с настолками»** стоит в торговом зале, библиотеке, жилых комнатах и жилых отсеках. Настолки чаще попадаются и в книжных шкафах. Тест: из обычных зданий оружие выпадает больше чем в 3% бросков, настолки — больше чем в 2%.
- **Старт**: 2 трубы, нож и кирка (без кирки первая же разметка у входа упиралась в камень и стояла вечно — нашли это e2e-тестом стройки). Если разметка упирается в породу без инструмента, это видно в «Задачах»: «Камень — нужна кирка».

### Нарастающая сложность
- **Уровень угрозы** (1–10) = 1 + (средний уровень игроков − 1) · 0,7 + (день − 1) / 5. Враги получают +10% здоровья и +2% к попаданию за каждый уровень угрозы сверх первого. В зданиях, куда вы входите впервые, их больше (+1 к опасности за каждые 3 уровня). Налёты по-прежнему растут с днями.
- Угроза видна в верхней плашке («☢ Угроза N»), о росте сообщает журнал.
- Опыт по-прежнему дают и дела в бункере, и вылазки. Добавлены +25 за выполненную просьбу жильца, +5 за впущенного беженца и +2 за разговор.

### Меньше ботов на старте, новые жильцы
- **На старте — не больше 3 жильцов-ботов** (`MAX_START_BOTS`), даже если в лобби выбрано 6.
- **Интерком у гермодвери.** Первый гость — беженец утром второго дня, дальше кто-то звонит примерно раз в 1,2–2,6 дня. Беженца можно впустить, расспросить (проверка ХАР: врёт или нет), дать консерву и отказать или не открывать. Каждый пятый — разведчик налётчиков: если впустить не расспросив, у двери начинается засада. Через интерком же приходят **торговцы**, с настоящим обменом со склада, и **незнакомцы из событий «у двери»**, где решает тот, кто ответил. Пока звонят, лампочка на интеркоме мигает. Если никто не подошёл, гость уходит. В партии из одних ботов жильцы отвечают сами: впускают, пока есть место и еда.
- **На вылазках** выжившие попадаются чаще: люди в здании с шансом 45% вместо 30%, «одинокий выживший» — вдвое чаще.
- Симулятор (4 жильца, 12 дней, 3 сида): колония растёт до 7 человек к 10-му дню и упирается в еду к 11–12-му — стимул ходить на вылазки. 0 смертей.

### Разговоры с жильцами
- Действие «💬 Поговорить» у жильца. **Раз в день у каждого своя история**: воспоминание по профессии, тревога по состоянию (голод, усталость, раны, тоска) или радость. Ответов три: выслушать, подбодрить, пошутить (проверка ХАР). Ответ поднимает рассудок и отношения.
- **Иногда — просьба, привязанная к состоянию бункера**: «фильтр забился», «проводка искрит», «вода отдаёт ржавчиной», «нужна комната отдыха / медпункт / мастерская», «принеси с вылазки…». Согласие добавляет запись в «Задачи» (💬). Когда бункер приходит в нужное состояние, просьба засчитывается сама: жилец благодарит (+15 рассудка и отношений), вы получаете +25 опыта.

### Мини-игры в каждом деле
- Когда игрок начинает дело, открывается окно мини-игры. Руками получается быстрее и лучше. Закрыли окно («Пусть делает сам») — персонаж доделывает сам в обычном темпе. Пока окно открыто, само дело почти стоит (×0,25). Боты не играют.
- Восемь механик:
  - **насос** — тянуть рукоять вниз и вверх, мышью или W/S;
  - **педали** — A/D по очереди в ритм; ровный ритм даёт до ×1,8 тока, сбой — ×0,6;
  - **оттирание** — фильтр воздуха, уборка, посуда, клетка, трубки;
  - **вращение** — вентиль водоочистки, лампочка (в ремонте ламп), половник при готовке (слишком быстро — расплескали);
  - **тайминг** — ПРОБЕЛ в зелёной зоне: болты при ремонте и обслуживании, гвозди при каркасе и укреплении, удары кирки при копке;
  - **полив** — держать и отпустить на черте;
  - **pH раствора** — держать стрелку в зоне;
  - **клики** — урожай, жуки, цветы, сухие листья.
- Сервер принимает «импульсы» (`mg`) не чаще раза в 0,12 с. Импульс — кусок дела или несколько секунд работы для бессрочных дел (копка, каркас).

### Совет — «непонятно, что решаем»
- Над каждым шагом — шкала «Шаг 1 из 3» и пояснение простыми словами:
  - что значит паёк 0 / ½ / 1 / ×2 и кто может его менять;
  - как голосуют и что такое «🎲 проверка»;
  - зачем доска плана и почему кто-то спит на полу;
  - когда совет идёт дальше.
- В пайках видно, на сколько дней останется еды при норме, или что её не хватит.

### «Сбросить припасы на склад»
- Кнопка «Сложить на склад» была, но только рядом со стеллажом. Теперь, если в руках вещь для склада, в любом месте бункера есть «📥 Отнести на склад»: персонаж сам идёт к ближайшему стеллажу и раскладывает.

### Карта
- Сгенерирована один раз (`node scripts/gen-map.mjs`) и закоммичена: **карта района Новоград** (`client/public/assets/wasteland-map.svg`). На ней:
  - река Сорока и три моста;
  - Южное шоссе, железная дорога;
  - кварталы Центра, Заречья, Промзоны и Вокзала;
  - трубы заводов, парк;
  - Мёртвый квартал и воронка эпицентра;
  - Холм с изолиниями, лес, поля, Северные горы;
  - картуш «Карта гражданской обороны», компас, масштаб.
- **Разметка** (`shared/src/data/mapslots.json`) — 37 фиксированных мест и 50 дорог между ними. Каждое место — либо конкретная локация (больница на Проспекте Созидания, КПП у мостов, телевышка на Холме, барахолка у вокзала, воронка), либо набор допустимых типов для сида. География одинакова в каждой партии, содержимое и названия меняются. Путешествовать можно только по нарисованным дорогам. Неразведанные места — «?» на своём участке, без спойлеров. Тест: все места достижимы от дома.

### Живой мир
- **Ядерный удар в прологе.** По радио ГО идёт отсчёт: «Воздушная тревога!» → «удар по Северному району» → «вторая волна, связь с Промзоной потеряна» → «гермодвери закроются через двадцать секунд» → шипение. Над горизонтом три вспышки: сначала свет, через секунду гул и тряска камеры, и растут грибовидные облака — от белого через оранжевый к грязно-серому. С первого удара сыплется пепел. На последней секунде — «Вспышка» над районом, долгий раскат и сильная тряска.
- **Бункер живёт сам** (`sim/ambience.ts`, раз в 55–120 с): далёкий взрыв (тряска, пыль с потолка, немного грязи, −1 рассудка), крысы пробегают по комнате, лампы мигают (чаще при слабом аккумуляторе), трубы стонут, в вентшахте воет ветер (чаще в бурю). Жильцы реагируют вслух, соседи переговариваются.
- Найденный по пути баг: полноэкранная вспышка удара перекрывала интерфейс и глотала клики. Правило `#ui > *` перебивало `pointer-events: none`; у полноэкранных слоёв теперь `!important`.

## Итерация 3б: Docker, звук и музыка, гитара, болтовня, утренний кофе

- **Docker и CI.** `Dockerfile` собирает клиент и запускает сервер через tsx в одном образе (порт 8080, сохранения в томе `/data`). `docker-compose.yml` берёт образ `ghcr.io/mrmigles/bunker:latest` или собирает локально (`--build`). `.github/workflows/docker.yml`: проверка типов, тесты и сборка клиента, затем образ публикуется в GHCR (`latest` для `main`, короткий sha, теги `v*`). Код опубликован в github.com/mrMigles/bunker.
- **«Звука нет».** Проверил в браузере: звуковой движок работает, сигнал доходит до выхода. Но в игре почти ничего не звучало. Музыка была только в радио. Гул генератора на 50 Гц на динамиках ноутбука не слышен. Звуки проигрывались только на событиях.
- **Фоновая музыка** (`client/src/audio/soundtrack.ts`) генерируется на лету, у каждого настроения свой слой, переход плавный:
  - **бункер** — тёплые пэды и неспешное арпеджио (Dm7–G–B♭maj7–Am);
  - **ночь** — то же, медленнее и реже;
  - **вылазка** (и пролог) — низкий гул, пульс сердца, далёкие одинокие ноты;
  - **бой** — барабаны, минорный бас-остинато, аккорды.
  - Бой включается быстро, остальные настроения наплывают за несколько секунд. Радио приглушает музыку. Громкость — ползунок «Музыка» в настройках.
- **Гитара.** Раньше гитара из пролога становилась «полкой с личными вещами», и играть на ней было нельзя. Теперь она ставится на стойку в жилом отсеке: «🎸 Взять гитару и сыграть» (клавиши A S D F G H J K L ;). Боты на досуге играют сами, соседи рядом слушают, и им становится легче. Гитару можно найти и на вылазке — в полках с настолками и среди разных мелочей. Дома её сразу ставят на стойку.
- **Разговоры — не всегда задание.** Просьба теперь выпадает в 28% разговоров вместо 50%. В остальных — лёгкая болтовня, анекдоты (с ответами «Посмеяться», «Рассказать свой», «Бородатый…») и истории. Боты между собой тоже чаще болтают о пустяках и травят анекдоты, собеседник смеётся в ответ.
- **Утренний кофе.** С 6:10 до 8:40 большинство жильцов садятся за общий стол в столовой, каждый на своё место. Пьют «кофе» из цикория, болтают о пустяках, обсуждают планы на день, кто-то шутит. Это немного бодрит, утоляет жажду и поднимает рассудок, в компании сильнее.

## Итерация 4: управление в прологе, обучение, «Убежище» и «Персонаж», редактор персонажа

### Управление в прологе
- Панель прологa была устроена иначе, чем в бункере: кнопки без клавиш, выделения нет. Теперь это то же меню «Рядом с вами»: выделенное действие с плашкой **E**, остальные с номерами, **↑/↓** листают. «Бросить соседу» — **Q**, «Отнести в убежище» — **Пробел**.
- Строка подсказок внизу экрана меняется по режиму: пролог, бункер, здание, стройка, бой. Раньше везде висело «Мышь · WASD · Esc».

### Обучение (`client/src/ui/tips.ts`)
- 20 карточек-подсказок. Каждая появляется, когда становится актуальной, а не всё сразу в начале:
  - пролог и «руки заняты»;
  - первый день; потребности; «Убежище и персонаж»;
  - первая мини-игра, стройка, вещи в руках;
  - сборы на вылазку, карта, первое здание, «слишком шумно»;
  - первый бой, ночной совет, звонок интеркома, разговоры со 2-го дня, новый уровень;
  - нехватка еды, рост угрозы, налёт.
- Карточка не блокирует игру, показывается одна за раз и каждая — один раз (помнит браузер). Уходит сама, когда её момент прошёл, или через 40 секунд. «Выключить подсказки» — сразу; «Показать подсказки заново» — в настройках.

### «Убежище» и «Персонаж»
- Кнопка «Инвентарь» переименована в **«Убежище»** (Tab): склад, доска дел, газета, рецепты — это управление базой.
- Новая кнопка **«Персонаж»** (I), три вкладки:
  - **Снаряжение**. Слоты «Оружие», «Защита», «Инструмент» — у себя и у каждого жильца-бота (спутника). Вещь берётся со склада и остаётся при владельце; снятая возвращается на склад, после смерти владельца — тоже. Своё оружие и броня идут в бой (`charUnit`) и на вылазку. Фонарь в слоте даёт свет без фонаря в рюкзаке, противогаз снижает радиацию, ПНВ даёт ночное зрение. Здесь же видно, что у кого в руках: можно передать вещь спутнику и забрать у него, если стоите рядом (до 4 шагов). Персонажа другого игрока трогать нельзя.
  - **Прокачка**. Уровень и опыт, выбор нового умения, изученные умения, 8 навыков с прогрессом до следующего уровня, характеристики и черты.
  - **Досье**. Профессия, возраст, фобия, багаж; отсюда же открывается подробная карточка.

### Создание персонажа — это же РПГ
- В лобби есть кнопки **«✏ Создать своего»** и **«🎨 Изменить выбранного»**. В редакторе:
  - имя, пол, возраст, профессия;
  - **15 очков** на пять характеристик, каждая от 1 до 5;
  - сильная черта и слабость (с описанием), фобия, багаж;
  - **внешность**: цвет одежды, головной убор (13 вариантов плюс «без головного убора»), тон кожи (5), цвет волос (6).
- **Живое 3D-превью**: та же полигональная фигурка, что в игре, медленно поворачивается.
- Сервер проверяет карточку (`validateCustomCard`) и добавляет её четвёртой, с пометкой «свой». Личная цель остаётся тайной: у изменённой карточки своя, новой достаётся случайная. Кожа и волосы теперь хранятся в карточке и видны везде: в бункере, прологе, на вылазке, в бою.

### Мелочи
- Первая дверь за лестничным холлом больше не бывает запертой: e2e новичка упёрся в неё, а новый игрок на первой вылазке — тем более.
- Юнит-тесты: 130 (новые — `iter4.test.ts`: своё оружие в бою, одевание и передача вещей спутнику, проверка своей карточки). e2e `scripts/e2e/iter4.mjs` — 12 шагов, все проходят. `newcomer`, `iter3` тоже проходят.

## Итерация 5: исправления по игре и по ролевому аудиту

- **Ручная копка «не работает».** На сервере копка шла, но у бессрочных дел (копка, каркас) в данных не было прогресса, и персонаж просто стоял без полоски. Теперь прогресс считается по вскопанной доле клетки и готовности каркаса; он виден над персонажем и в окне мини-игры.
- **Настолки.** Над столом — места: кто сидит, игрок или бот, кто сейчас ходит (подсвечено). Появился журнал партии: каждый ход с автором, последние 12 строк.
- **Перестановка.** На полках памятных вещей стояла только пустая доска: для «keepsake» было два одинаковых `case`, и первый, пустой, перекрывал второй. Теперь видны гном, мишка, альбом, утюг, приёмник. Гитару на стойке можно переставлять, пока на ней никто не играет.
- **Без прокрутки.**
  - Окно сборов: две колонки (отряд слева, рюкзак справа в три столбца), кнопка «Выйти на поверхность» всегда видна.
  - Панель карты, совет и редактор персонажа (две колонки) помещаются на 1366×768.
  - Широкие окна до 1180 px.
  - `scripts/e2e/screens.mjs` снимает окна на ноутбучном разрешении и сообщает, где осталась прокрутка.
- **Не садиться друг на друга.** У общего стола три стула (`claimSeat`). Кому места не хватило, стоит рядом с кружкой (поза `sip`), и это немного портит настроение — и за кофе, и за едой.
- **Велосипед сменами.** Бот крутит около 50 секунд, затем отдыхает полтора игровых часа, а велосипед простаивает 15–35 игровых минут до следующего. Время считается в игровых часах: первая версия отсчитывала его по часам фазы, которые сбрасываются каждый день, и на второй день симулятор показал полное обесточивание. Поймано и исправлено; симулятор (10 дней, 3 сида): вода и энергия стабильны, 0 смертей.
- **Один тип врагов.** Волна на шум — несколько врагов одного типа (первая — от 60 шума, вторая — от 90, не раньше чем через 45 с и только если никто уже не бежит). В бою на вылазке участвует один тип врагов — тот, кто заметил вас, и такие же рядом, не больше трёх.
- **Клик = быстрый обыск (баг).** Кнопка под курсором перерисовывалась, когда начинался обыск, и её `pointerup` не доходил, поэтому удержание считалось бесконечным. Теперь отпускание ловится на уровне окна. Быстрый обыск — только если держать E или кнопку; e2e это проверяет.
- **Быстрый обыск громче:** +12 шума в секунду (было 4,5), шанс что-то уронить — 20% в секунду.
- **По аудиту** (`PLAYER_ROLE_REVIEW.md`, раздел «Ответы разработки»):
  - подписи бункера не видны в вылазке;
  - «всё рядом» в меню выбранного объекта;
  - звонок интеркома — в «Задачах»;
  - кнопки диалогов больше не пропадают под курсором;
  - одиночный совет ждёт «Готов»;
  - одинаковое время пути на карточке и в журнале;
  - «Наш бункер» вместо `home`;
  - без противоречивых черт и одинаковых имён;
  - «с добычей N%» вместо «успех»;
  - «Фонаря нет» видно сразу;
  - строки копки называют комнату и этаж.

## Итерация 6: запуск на сервере, телефоны, PWA и обновления, Telegram, мультиплеер

- **Падение на сервере** (`Assertion failed: ... uv_thread_create`). Node не мог создать поток: glibc-образ вызывает `clone3`, а seccomp-профиль старого Docker его запрещает. Образ переведён на `node:24-alpine` (musl не использует `clone3`). Добавлены `HEALTHCHECK` через `/healthz`, `init: true` в compose (сигнал остановки доходит до сервера, и он успевает сохранить партии). В compose в комментарии оставлен запасной вариант — `seccomp:unconfined`.
- **Телефон.** Сенсорный экран без мыши включает мобильный режим (можно принудительно: `?mobile=1/0`).
  - Контекстные кнопки не вводят новой логики: они посылают те же `KeyboardEvent`, что и клавиатура. Поэтому каждый экран, который понимает `E`, `Q`, `G`, `[`, `]`, `Esc`, сразу работает с телефона.
  - Джойстик вливается в `axis()`. На вылазке лёгкий наклон значит «красться»: там `Shift` — это крадучись, а не бег.
  - Щипок и сдвиг — двумя пальцами. Жест из двух пальцев никогда не превращается в клик: раньше второй палец открывал карточку жильца под собой.
  - Касание кнопки, которая исчезает под пальцем (сменился режим), не проваливается кликом в то, что под ней.
  - Тексты не дублируются: `MutationObserver` на телефоне меняет «Щёлкните» на «Коснитесь» и убирает «(Esc)», «(E)» во всех окнах, включая будущие. У подсказок обучения есть отдельные тексты для пальцев.
  - Раскладка на 844×390: карточка жильца уходит от джойстика; на вылазке панель здания уходит наверх; бой и совет ужаты по высоте; «Готов» совета прилипает к низу панели.
- **Кнопки, которые не нажимаются.** Совет перерисовывался каждую секунду из-за таймера, и «Готов» мог уйти из-под курсора между нажатием и отпусканием. Теперь таймер тикает на месте, а панель перерисовывается только при изменении данных. Лобби при перерисовке сохраняет прокрутку: на телефоне оно выше экрана.
- **Удержание в меню «Рядом с вами»** (педали, копка) теперь работает и мышью, и пальцем: нажали — начали, отпустили — перестали. Раньше клик запускал «удерживаемое» дело без конца.
- **PWA и доставка обновлений.** Выбрана самописная схема из 40 строк в `vite.config.ts` вместо плагина: так видно и проверяемо, что именно кэшируется.
  - `BUILD_ID` приходит в сборку (в CI — SHA коммита) и становится именем кэша.
  - HTML, `sw.js` и манифест — `no-cache`, хэшированные бандлы — `immutable`.
  - Навигация — сначала сеть. Активация нового worker удаляет все старые кэши.
  - Переключение решает страница. В меню — сразу. В партии — плашка «Обновить / Позже», чтобы не рвать бой; после «Обновить» — возврат в тот же бункер.
  - Независимо от worker опрашивается `/version`.
  - `scripts/e2e/pwa.mjs` проверяет всё это на двух настоящих прод-сборках.
- **Возврат в игру.** Вкладка помнит свой бункер (`sessionStorage`), поэтому перезагрузка или выгрузка вкладки телефоном возвращает туда же. Обрыв связи — до 8 попыток переподключения. Новая вкладка по-прежнему начинает с меню.
- **Telegram.** Бункер привязан к чату: код `T…` получается хэшем из `start_param`, id группы или `chat_instance`.
  - Личность игрока `tg_<id>` подписана HMAC и привязана к коду бункера. Поддельный или чужой `tg_` превращается в гостя; в бункер `T…` без Telegram-личности не пускают.
  - Обычные коды никогда не начинаются с `T`.
  - Имя — «Имя Ф.» из Telegram. Меню и код скрыты.
  - Без `TELEGRAM_BOT_TOKEN` сервер верит `initData`: так работают разработка и e2e. На проде токен обязателен (записано в README).
- **Мультиплеер.** Проверен `scripts/e2e/multi.mjs` на двух браузерах:
  - вход по коду;
  - хост — только создатель;
  - видно движение друг друга в прологе и в бункере;
  - чат;
  - обрыв сокета и перезагрузка возвращают в того же персонажа без дубликата игрока;
  - совет ждёт «Готов» от обоих.
  Найденная проблема — «Готов» совета уходил из-под курсора — исправлена (см. выше).

## Итерация 7: полив, готовка, сон, снаряжение, энергия, шум, бой, дерево

- **Полив.** Действие поливало одну грядку, а мини-игра рисовала «грядка 1 из 3». Остальные лотки оставались на 55%, и казалось, что полив не работает. Теперь один заход лейки поливает все грядки комнаты, которым нужна вода. Первой идёт грязная вода: 0,2 на грядку, растениям она годится. В меню пишется, сколько грядок и какой водой. В подсказке мини-игры сказано, что после третьей лейки всё готово. У «Воды» в верхней панели видна грязная вода (`Вода · гр. N`), а во всплывающей подсказке — что это и зачем.
- **Готовка.** Результат показывался только всплывающей надписью над поваром. Теперь в журнале пишется, что вышло и куда оно легло. Окно плиты показывает готовые блюда на складе, у рецептов виден состав, а недоступные рецепты приглушены.
- **Сон.** Тело ложилось левее койки и утопало в матрасе. Теперь поза сна своя: голова на подушке (левый край), тело на матрасе, ноги чуть согнуты. Отдельный debug-оп `tired` для проверки.
- **Выпадающие списки снаряжения закрывались.** Экран «Персонаж» перерисовывался каждые 300 мс, потому что в ключ входил весь персонаж: потребности и координаты меняются каждый тик. Теперь ключ собран только из показанного. Пока открыт список, панель не перерисовывается.
- **Энергия.**
  - Комнаты с техникой потребляют ток постоянно, от 0,02 до 0,1 кВт: техотсек, медпункт, мастерская, химлаборатория, водоузел, радиорубка, клуб и др. Чем больше бункер, тем больше нужно, и одного велосипеда рано или поздно не хватает.
  - В задачах появляется «Одного велосипеда уже мало», когда средний расход выше 85% от того, что могут дать генераторы.
  - В верхней панели у энергии стрелка ▲/▼ с балансом, во всплывающей подсказке — выработка, расход и что с этим делать.
  - Симулятор (10 дней, 3 сида, 4 игрока-бота): 0 смертей; батарея и раньше к 3-му дню садилась в ноль, отключения нагрузки — 5–30% (раньше 2–18%). Выработку ботов (~1 кВт) держат смены на велосипеде. Попытка укоротить отдых при пустой батарее ясного выигрыша не дала и откатана.
- **Обычный обыск шумнее.** Раньше +0,3/с при затухании 3,5/с, то есть шума вообще не было. Теперь +4,6/с: длинный обыск подряд накапливает шум. Обыск комнаты считается на каждого участника (+2,4/с), поэтому отряд целиком шумит сильнее. Быстрый обыск не трогали. Сценарий «пройти больницу тихо» в тестах теперь ждёт, пока шум уляжется между ящиками.
- **Бой сложнее.** У врагов на 20% больше здоровья, урон отряда на 10% ниже. Тест «3 бота против 5 слабых врагов»: боты всё ещё выигрывают больше половины. Вариант +30% / −15% опускал их ниже половины, от него отказались.
- **Выбор врага в бою.**
  - Щелчок выбирает ближайшую фигуру на экране: засчитывается и голова, и чуть рядом. Точное попадание в клетку или в табличку не нужно.
  - Подходящая цель подсвечивается ещё при наведении: красным — враг, зелёным — свой для лечения.
  - Таблички над соседями больше не лежат друг на друге: следующая поднимается на ряд выше с тонкой линией к фигуре.
- **Дерево.**
  - На вылазках появился контейнер «Штабель досок» (таблица `timber`: 2–4 дерева). Он стоит в амбаре, гараже, спортзале, классе, подсобке, тоннеле метро. Скамьи тоже дают доски.
  - В обычных ящиках дерево стало попадаться чаще.
  - Во всплывающей подсказке у «Дерева» написано, где его искать.
- **Найдено по дороге: работа отставала от часов.**
  - Прогресс дел считался в реальных секундах, а потребности — в игровых часах. Когда время ускорялось (все игроки отдыхают — ×3, отладочная скорость), жильцы ели и уставали в 3–10 раз быстрее, чем успевали работать. Ускоренная колония голодала, стройка вставала.
  - Теперь прогресс дел идёт по игровым часам (`timeMult`).
  - По той же причине боты «пили утренний кофе» почти весь день. Кофе теперь заканчивается в 9:30, а длина досуга делится на ускорение.
  - Недокопанная комната и грунт в ней получили чуть более высокий приоритет (0,64 и 0,52): колония доделывает начатое, и в бункере не остаются ямы с кучами земли.
  - Сквозной тест стройки проходит; тестовый игрок в нём отдаёт персонажа боту и сам отвечает на совете.

## Итерация 8: новый облик, телефонная раскладка, Telegram Games, постобработка

- **Облик.** Один стиль для всех экранов — `theme.css` по мотивам присланных макетов: тёплые янтарные рамки на тёмном стекле, шрифты Manrope (текст) и Russo One (логотип, крупные цифры).
  - Иконки — свой набор линейных SVG (`ui/icons.ts`, ~90 штук), окрашенных CSS. Шрифт иконок и внешние запросы не нужны.
  - Характеристики, потребности, навыки и ячейки снаряжения везде имеют свои постоянные иконку и цвет (`STAT_IC`, `NEED_IC`, `SKILL_IC`).
  - Эмодзи в начале заголовка окна превращается в иконку. Старые окна обновились без правок, новые пишутся так же.
- **Переделаны по макетам:** главное меню (логотип, поле имени, создание, вход по коду, список бункеров с иконками), лобби (карточки с портретом, пять характеристик плитками, черты, фобия, багаж, скрытая цель), досье жильца, «Убежище → Склад» (группы с иконками), «Персонаж» (портреты, ячейки с иконками, характеристики плитками), список «Отряд» (портрет и четыре полоски), окно «Меню».
- **Выход в меню** — кнопка в окне «Меню». Жилец остаётся в бункере под ботом, вкладка забывает свой бункер (иначе перезагрузка вернула бы обратно). В игре из Telegram вместо выхода подсказка закрыть окно крестиком: другого бункера у чата нет.
- **Телефон.** Раскладка рассчитана на худший случай — браузер с адресной строкой, ~760×300 CSS px (снимки игрока):
  - сверху одна полоса;
  - справа столбец иконок;
  - «Задачи» по умолчанию свёрнуты;
  - карточка жильца — пять полосок без подписей, по касанию открывает «Персонаж»;
  - журнал событий и подсказки клавиш скрыты;
  - окна открываются на весь экран, прокрутка одна, у окна сборов кнопки прижаты к низу.
  Отдельный `mobile.css`. Старые телефонные правила, разбросанные по `polish.css`, удалены.
- **Установка на телефон** со второго игрового дня:
  - на Android — настоящее `beforeinstallprompt`;
  - на iPhone — подсказка про «На экран «Домой»»;
  - «Позже» спросит через три игровых дня, «Не предлагать» — больше никогда;
  - не показывается в Telegram и в уже установленной игре.
- **Telegram Games вместо одного Mini App.** Игрок хотел «в чате стартовал — и все из чата в одном бункере». Это и есть платформа Telegram Games: `/play` → карточка игры с кнопкой «Играть» для всех в чате.
  - Бот на сервере опрашивает Telegram (long polling, без вебхука).
  - На нажатие «Играть» бот отвечает ссылкой с подписанным токеном: ключ чата, id и имя игрока, время.
  - Ключ чата — `chat_instance`. Его же получает Mini App, открытый из того же чата, поэтому оба пути ведут в один бункер.
  - Mini App остаётся вторым входом.
  - Для e2e есть `/api/tg/dev-token` (только не в production).
- **Постобработка** (`render/postfx.ts`, на один общий рендерер):
  - ACES-тонмаппинг;
  - мягкое свечение ламп и огня (UnrealBloom);
  - грейд: контраст, насыщенность, тёплые света и холодные тени;
  - виньетка, мелкое плёночное зерно, лёгкая хроматическая аберрация по краям;
  - красная кромка по краям, когда плохо: бой, свой жилец без сознания или при смерти.
  Качество: «Кино», «Лёгкая» (без свечения, по умолчанию на телефонах) или «Выкл.». В автоматизированном браузере (e2e) эффекты выключены: он рисует на процессоре, и свечение замедляло игру.
